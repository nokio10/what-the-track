# What The Track — музыкальная игра «Угадай продолжение песни»

Веб-игра для компании: ведущий собирает вопросы из треков Яндекс Музыки, а игроки слушают фрагмент, видят текст вопроса с пропущенным словом и пытаются быстрее остальных угадать продолжение.

Игра состоит из двух частей:

- `admin`-интерфейс для ведущего
- `player`-интерфейс для игроков

Во время подготовки система:

- скачивает треки по ссылкам из Яндекс Музыки
- берёт текст песни из Яндекса, а если его нет — распознаёт сама
- подбирает «слово вопроса»
- режет аудио на вопрос и ответ
- сохраняет готовую игру локально

Во время самой игры всё работает уже из локально подготовленных файлов.

## Режимы распознавания

Главная трудность — треки, для которых в Яндекс Музыке нет текста: вопрос
приходится строить из того, что услышала модель. Для них есть два режима.

| | что нужно в `.env` | трек с текстом в Яндексе | трек без текста |
| --- | --- | --- | --- |
| **Яндекс + Whisper** | `YANDEX_TOKEN` (или токен в админке) | официальный текст, таймкоды от WhisperX | вокал отделяется (Mel-Band RoFormer), WhisperX распознаёт, алгоритм выбирает слово |
| **Согласие трёх моделей** | плюс `HF_TOKEN` | так же | WhisperX и две GigaAM v3 слушают исходный микс, в вопрос идут только слова, которые все три услышали одинаково |

Согласие включено по умолчанию (`CONSENSUS_MODE=on`), но без `HF_TOKEN` оно
само уступает место режиму «Яндекс + Whisper» — переключать ничего не нужно.
`CONSENSUS_MODE=off` выключает его совсем. Подробности — в разделе «Треки без
текста» ниже.

Если согласие не нужно вовсе, образ GigaAM можно и не собирать: поставьте в
`.env` `CONSENSUS_MODE=off` и поднимайте только три сервиса (для GPU добавьте
`-f docker-compose.yml -f docker-compose.nvidia.yml`):

```bash
docker compose up -d --build --no-deps nginx game-app generator
```

```bash
cd what-the-track

```

Впишите в `.env` пароль ведущего и токен Яндекс Музыки (как его получить —

```bash

```

Откройте [http://localhost:5002/admin](http://localhost:5002/admin) — дальше всё
в разделе «Как начать игру с нуля».

## Что это за игра

Механика раунда:

1. Ведущий запускает следующий вопрос.
2. На экране игроков появляется фраза с пропуском: `... ___`.
3. На устройстве ведущего проигрывается аудио-вопрос.
4. После окончания фрагмента игрокам открывается ввод ответа.
5. Игроки отправляют своё слово.
6. Ведущий показывает правильный ответ.
7. Система начисляет очки и обновляет таблицу.

Цель игрока:

- угадать пропущенное слово в продолжении песни
- набрать больше очков, чем остальные

По текущей логике:

- за правильный ответ даётся `+2` очка
- ответы короче `4` символов не принимаются
- в Whisper-only вопросах может показываться дополнительная подпись к треку, чтобы игрокам было проще сориентироваться

## Как устроен проект

Сервисы:

- `game-app` — Flask + Socket.IO, игровая логика и веб-интерфейсы
- `generator` — генерация вопросов, обработка аудио, Whisper/разделение вокала
- `gigaam` — две модели GigaAM v3 для треков без текста (см. «Треки без текста»)
- `nginx` — входная точка для браузера, прокси для Socket.IO и раздача медиа

Основные адреса после запуска:

- интерфейс игроков: [http://localhost:5002/](http://localhost:5002/)
- интерфейс ведущего: [http://localhost:5002/admin](http://localhost:5002/admin)

Генератор и `gigaam` наружу не публикуются: игра ходит к ним по внутренней сети
compose, и поставить задачу генерации в обход админки нельзя.

Важно:

- открывать игру нужно именно через `nginx` на порту `5002`
- прямой доступ к `game-app` в браузере не нужен
- именно `nginx` корректно проксирует `/socket.io/` и `/media/`

## Что понадобится

Минимально:

- Docker
- Docker Compose
- доступ в интернет для первой сборки и генерации треков
- токен Яндекс Музыки

- поддержка GPU в Docker

На Windows обычно это означает:

- Docker Desktop
- включённый WSL2 backend
- рабочая GPU-интеграция Docker Desktop

## Структура данных проекта

Рабочие папки:

- `media/` — готовые игры, mp3-файлы вопросов/ответов, архив игр
- `whisper_cache/` — кэш моделей Whisper/связанных загрузок
- `mdx_cache/` — кэш моделей для разделения вокала
- `gigaam_cache/` — кэш моделей GigaAM и pyannote
- `logs/` — журнал выбора вопросов для треков без текста (`consensus_log.jsonl`)
- `.env` — пароль ведущего, токены Яндекс Музыки и HuggingFace и переключатели;
  шаблон с пояснениями — `.env.example`. В образы и в git `.env` не попадает
- `templates/` — HTML интерфейсы игрока и ведущего
- `static/` — статические файлы фронтенда

После генерации игры появляются, например:

- `media/ABCD-questions.json`
- `media/ABCD-media/...`

Где `ABCD` — ID конкретной игры.

## Пароль ведущего

Управлять игрой (создавать, генерировать, запускать вопросы, менять очки) может
только тот, кто знает пароль ведущего. Он задаётся в файле `.env` в корне
проекта:

```
ADMIN_PASSWORD=придумайте-пароль
```

`/admin` спросит пароль один раз и запомнит его в этом браузере. Если пароль
неверный, админка спросит снова. Без `ADMIN_PASSWORD` пароль не спрашивается —
так можно играть только в доверенной сети: любой, кто откроет `/admin`, сможет
управлять игрой. После смены пароля перезапустите стек (`docker compose up -d`).

## Быстрый старт на CPU

Запускать из корня проекта:

```powershell
docker compose up -d --build
```

После старта:

1. Откройте [http://localhost:5002/admin](http://localhost:5002/admin)
2. Создайте игру
3. Вставьте токен Яндекс Музыки (или один раз впишите его в `.env` как `YANDEX_TOKEN`)
4. Добавьте ссылки на треки/альбомы/плейлисты
5. Нажмите `Generate`

CPU-режим:

- проще в запуске
- медленнее генерирует вопросы. Замер на треке 1:44 (16 ядер): без текста в
  Яндексе (согласие трёх моделей) — полторы минуты, вопрос тот же, что на GPU;
  с текстом — около 18 минут, почти всё время уходит на отделение вокала
  Mel-Band. На GPU: без текста ~40 секунд на трек, с текстом — 1,5–2,5 минуты
  (тоже в основном отделение вокала)
- подходит для тестов и небольших партий
- все части — WhisperX (int8), GigaAM, разделение вокала — работают на процессоре

## Быстрый старт на GPU

Если у вас настроена NVIDIA GPU в Docker, запускайте так:

```powershell
docker compose -f docker-compose.yml -f docker-compose.nvidia.yml up -d --build
```

GPU-режим:

- заметно быстрее на этапах Whisper и обработки аудио
- лучше подходит для больших списков треков
- требует исправно настроенной GPU-среды

Если контейнеры запустились, но видеокарта внутри них не видна, генератор и
GigaAM сами переходят на CPU (WhisperX — int8 вместо float16): игра работает,
только медленнее. На машине совсем без NVIDIA GPU этот вариант не стартует —
Docker не может выдать контейнерам видеокарту; там запускайте CPU-вариант выше.

Если вы переключаетесь между CPU и GPU режимом, лучше сначала остановить текущий стек:

```powershell
docker compose down
```

А затем поднять нужный вариант заново.

## Как остановить проект

CPU-стек:

```powershell
docker compose down
```

GPU-стек:

```powershell
docker compose -f docker-compose.yml -f docker-compose.nvidia.yml down
```

## Как перезапустить только nginx

Обычно это не нужно, потому что `nginx` поднимается автоматически вместе со всем стеком.

Если нужен именно рестарт:

```powershell
docker compose restart nginx
```

Если вы хотите отдельно поднять `nginx`, можно использовать:

```powershell
docker compose up -d nginx
```

Но на практике проще и надёжнее запускать весь стек целиком.

## Как получить токен Яндекс Музыки

В админке уже есть ссылка `Get Token Here`, но можно сделать и вручную.

### Способ через интерфейс

1. Откройте [http://localhost:5002/admin](http://localhost:5002/admin)
2. Создайте игру кнопкой `Create Game`
3. Нажмите `Settings`
4. В блоке `Yandex Token` нажмите `Get Token Here`
5. Авторизуйтесь в Яндексе
6. Разрешите доступ
7. После редиректа скопируйте значение `access_token` из адресной строки

Пример:

```text
https://oauth.yandex.ru/verification_code#access_token=....&token_type=bearer&expires_in=...
```

Вам нужен именно кусок после `access_token=` и до следующего `&`.

### Прямая ссылка

Если удобнее, можно открыть OAuth напрямую:

[https://oauth.yandex.ru/authorize?response_type=token&client_id=23cabbbdc6cd418abb4b39c32c41195d](https://oauth.yandex.ru/authorize?response_type=token&client_id=23cabbbdc6cd418abb4b39c32c41195d)

### Токен в `.env`

Чтобы не вставлять токен в каждую игру, впишите его один раз в `.env` в корне
проекта и перезапустите стек:

```
YANDEX_TOKEN=...
```

Если поле `Yandex Token` в настройках игры пустое, генератор возьмёт токен
отсюда; вставленный в поле токен важнее.

### Важно про токен

- не публикуйте токен в открытом доступе
- если генерация перестала скачивать треки, возможно токен устарел или был отозван
- в таком случае просто получите новый и вставьте его снова

## Какие ссылки можно добавлять

В поле `Track Links / Playlists` можно вставлять ссылки Яндекс Музыки:

- на отдельные треки — `https://music.yandex.ru/album/123/track/456` или `.../track/456`
- на альбомы — `https://music.yandex.ru/album/123`
- на плейлисты пользователей — `https://music.yandex.ru/users/<логин>/playlists/<номер>`

Альбомы и плейлисты раскрываются в список треков, в логе генерации видно,
сколько треков нашлось. Ссылки других форматов генератор пропускает и пишет об
этом строку в лог.

Рекомендуется:

- одна ссылка на строку
- не смешивать много мусора в одном поле
- вставлять обычные ссылки из браузера/приложения Яндекс Музыки

В проекте есть защита от дублей: если в списке попадутся одинаковые треки, система постарается не скачивать их повторно.

## Как начать игру с нуля

Полный сценарий для ведущего:

1. Поднимите стек через Docker.
2. Откройте админку: [http://localhost:5002/admin](http://localhost:5002/admin)
3. Нажмите `Create Game`.
4. Откройте `Settings`.
5. Вставьте токен Яндекс Музыки.
6. Вставьте список ссылок.
7. Нажмите `Generate`.
8. Дождитесь окончания генерации по логам в окне статуса.
9. Нажмите `Start Rounds`.
10. Подключите игроков.
11. Нажимайте `Next`, чтобы запускать вопросы.

## Как подключить игроков

Игроки подключаются через отдельную страницу:

[http://localhost:5002/](http://localhost:5002/)

Что делает игрок:

1. Открывает ссылку в браузере
2. Вводит своё имя
3. Нажимает `Join`
4. Ждёт начала раунда

Важно понимать текущую механику:

- игроки не вводят код игры вручную
- они подключаются к текущей активной игре на этом экземпляре сервера
- ID игры нужен ведущему для идентификации и архива, а не для ввода игроком

Если игрок перезагрузил страницу или переподключился:

- из того же браузера можно снова зайти под тем же именем — счёт и ответ
  сохранятся (браузер помнит постоянный id игрока)
- с другого устройства или браузера это имя занять нельзя, даже пока его
  владелец не в сети: игра попросит выбрать другое. Если игрок сменил телефон,
  ведущий удаляет его старую запись и при желании возвращает очки кнопками `+`
- игрок не в сети не задерживает раунд: ответ показывается, когда ответили все,
  кто на связи, а право листать вопросы с телефона (у первого вошедшего игрока)
  переходит к следующему игроку на связи

## Как проходит раунд на практике

Есть важный нюанс текущего UX:

- аудио вопроса и аудио ответа проигрываются в админском браузере
- игроки обычно сидят со своих телефонов
- ведущий выводит звук через колонки, ноутбук, телевизор или проектор

То есть типичный сценарий такой:

1. Ведущий открывает админку на ноутбуке
2. Игроки открывают player-страницу на телефонах
3. Ведущий запускает вопрос
4. Все слушают звук с устройства ведущего
5. Игроки отправляют ответы со своих устройств

Из-за ограничений браузеров иногда полезно один раз кликнуть по странице админки перед первым вопросом, чтобы аудио точно разрешилось.

## Кнопки ведущего

Основные кнопки в `admin`:

- `Create Game` — создать новую игру
- `Settings` — токен Яндекса, ссылки на треки и запуск генерации
- `Saved` — архив ранее подготовленных игр
- `Start Rounds` — начать раунды по уже сгенерированным вопросам
- `Next` — следующий вопрос
- `Repeat` — повторно проиграть вопрос
- `Answer` — показать правильный ответ
- `Finish Game` — завершить текущую игру

Дополнительно ведущий может:

- вручную добавлять и снимать очки
- удалять игроков из сессии
- загружать старые сохранённые игры из архива

## Сохранённые игры

Если генерация уже была выполнена, игру можно не пересобирать заново.

Для этого:

1. Откройте `Saved`
2. Выберите игру из архива
3. Загрузите её
4. Нажмите `Start Rounds`

Это удобно для:

- повторных запусков одной и той же подборки
- тестов без повторного скачивания треков
- быстрых вечеринок на уже готовом наборе вопросов

## Что происходит во время генерации

Во время подготовки вопросов сервис обычно делает следующее:

- скачивает треки из Яндекс Музыки
- пытается получить LRC/текст
- если текста нет, использует Whisper
- выделяет вокал
- выравнивает текст и таймкоды
- выбирает слово-ответ
- собирает текст вопроса
- режет аудио на вопрос и ответ
- сохраняет результаты в `media`

### Треки без текста: согласие трёх моделей (`CONSENSUS_MODE`)

Если у трека нет текста в Яндекс Музыке, вопрос строится так:

1. WhisperX (без промпта) и две модели GigaAM v3 распознают **исходный микс** —
   без отделения вокала;
2. в вопрос идут только слова, которые все три модели услышали одинаково, и
   перед которыми подряд подтверждены ещё хотя бы три слова;
3. ответом не становятся служебные слова («чтобы», «такая») и слова, с которых
   начинается фраза (GigaAM пишет их с заглавной или ставит перед ними знак);
4. первыми идут слова в конце фразы — после них GigaAM ставит «.», «!» или «?»,
   затем запятую или делает паузу; внутри — сначала существительные;
5. если на миксе годного слова нет — отделение вокала BS-RoFormer и тот же
   отбор, но слово должны слышать хотя бы две модели и на миксе. Иначе трек
   пропускается: неверный вопрос хуже, чем никакого.

Режим подобран в исследовательской части проекта (в репозиторий она не входит).
По замеру на 63 треках: вопрос есть на всех, ответ в конце строки в
52 случаях из 62, неверных ответов нет (старый путь ошибался примерно на каждом
пятом треке). Продовые контейнеры на тех же 63 треках выбрали ровно те же
вопросы, что лаба, за 48 минут на RTX 5060 Ti: ~3 минуты скачивания, дальше в
среднем 39 секунд на трек; трек, которому нужен BS-RoFormer, — около 3 минут.
Каждое решение пишется в `logs/consensus_log.jsonl` — там есть
ответы, поэтому журнал лежит вне `media`, которую раздаёт nginx.

| значение | что происходит |
| --- | --- |
| `on` (по умолчанию) | как описано выше |
| `off` | только старый путь: Mel-Band → WhisperX |

GigaAM работает в отдельном контейнере `gigaam` и стартует вместе с остальными.
Ему нужен токен HuggingFace с принятыми условиями `pyannote/segmentation-3.0`.
Токен лежит в файле `.env` рядом с compose-файлами — compose читает его сам, в
образы он не попадает:

```
HF_TOKEN=...
CONSENSUS_MODE=on
```

При старте `gigaam` делает пробный прогон (проверяет токен и VAD); пока он не
закончился, генератор ждёт до 3 минут. Если сервис не поднялся, у него нет
токена или пробный прогон не прошёл, генерация не ломается: треки без текста
идут старым путём, а в логе генерации есть строка с причиной. Следующая попытка
обратиться к GigaAM — не раньше чем через 10 минут. Если же сервис работает, но
не смог распознать отдельный трек, старым путём идёт только этот трек.

Видеопамять в простое свободна. Каждая генерация идёт в отдельном процессе и
отдаёт видеопамять сразу, как закончится. Модели GigaAM загружаются на первом
треке без текста и выгружаются после минуты простоя (`GIGAAM_IDLE_UNLOAD_SEC`
в `.env`, по умолчанию 60). Цена — около 15 секунд на первом треке без текста
после простоя; пока такие треки идут подряд, модели не выгружаются.

Треки, для которых текст найден, этот режим не затрагивает.

Из-за этого первая генерация может занимать ощутимое время, особенно:

- на CPU
- на большом количестве треков
- при пустом кэше моделей

## Правила ответов

На текущий момент:

- ответ игрока должен содержать минимум `4` символа
- слишком короткие ответы интерфейс не отправит
- сервер дополнительно проверяет это правило

Это сделано специально, чтобы отсечь слишком короткие и шумные варианты.

## Nginx: зачем он нужен

`nginx` — это не дополнительная опция, а штатная точка входа в игру.

Он нужен для:

- доступа к `player` и `admin` страницам
- проксирования Socket.IO/WebSocket соединений
- раздачи локальных медиафайлов вопросов и ответов

Если открывать проект не через `nginx`, можно получить проблемы с:

- realtime-подключением
- `/socket.io/`
- загрузкой аудио из `/media/`

Поэтому для браузера используйте только:

- [http://localhost:5002/](http://localhost:5002/)
- [http://localhost:5002/admin](http://localhost:5002/admin)

## Как подключать игроков по сети

Если игра крутится не только локально, а на сервере или в локальной сети, игрокам нужно дать адрес nginx.

Примеры:

- `http://192.168.1.50:5002/`
- `http://my-domain.example.com/`

Ведущий открывает:

- `http://адрес/admin`

Игроки открывают:

- `http://адрес/`

Если поверх проекта стоит внешний reverse proxy или домен, важно не забыть проксировать:

- `/`
- `/socket.io/`
- `/media/`

## Типичные проблемы

### 1. Открывается страница, но игра не работает корректно

Проверьте:

- что вы открываете именно порт `5002`
- что поднят `nginx`
- что не пытаетесь ходить напрямую в `game-app`

### 2. Генерация очень медленная

Это нормально, если:

- вы используете CPU
- это первый запуск
- кэши моделей ещё пустые

Если есть GPU, лучше использовать GPU-стек.

### 3. Не скачиваются треки

Проверьте:

- актуален ли токен Яндекс Музыки
- есть ли интернет у контейнеров
- нет ли ошибок в логах `generator`

### 4. В браузере нет звука

Проверьте:

- что админ-страница открыта
- что браузер разрешил воспроизведение аудио
- что файл доступен через `/media/`
- что вопрос запускается через админку

### 5. Игроки не могут подключиться

Проверьте:

- что игра уже создана ведущим
- что игроки заходят по адресу nginx
- что WebSocket не режется внешним прокси

### 6. GPU-режим не стартует

Проверьте:

- видит ли Docker вашу NVIDIA GPU
- установлены ли драйверы
- включена ли GPU-поддержка Docker

## Рекомендуемый порядок работы на живой игре

Оптимальный сценарий для ведущего:

1. Поднимите проект заранее
2. Откройте админку
3. Создайте игру
4. Сгенерируйте вопросы заранее, до прихода игроков
5. Проверьте первый вопрос и звук
6. Дайте игрокам ссылку на player-страницу
7. Начинайте раунды

Так вы избежите пауз на скачивание, модели и подготовку прямо во время вечеринки.

## Коротко: самый быстрый сценарий

### CPU

```powershell
docker compose up -d --build
```

### GPU

```powershell
docker compose -f docker-compose.yml -f docker-compose.nvidia.yml up -d --build
```

1. Откройте `/admin`
2. Создайте игру

4. Добавьте ссылки на треки
5. Нажмите `Generate`
6. После генерации нажмите `Start Rounds`
7. Дайте игрокам ссылку на `/`

## Тесты

Логика вопросов, согласия моделей и игры проверяется без моделей и без
Docker — тесты берут функции прямо из исходников:

```bash
python -m unittest discover -s tests -t .
```

Тесты части речи запускаются, если установлен `pymorphy3`, а тесты сетевых
ошибок GigaAM — если установлен `requests`; без них они пропускаются.

## Правовые оговорки

- Треки скачиваются через ваш собственный токен Яндекс Музыки. Проект для
  личного использования на своих вечеринках; соблюдайте условия Яндекс Музыки.
- Сгенерированные игры (`media/`) содержат фрагменты песен и строки их
  текстов — не публикуйте их, они защищены авторским правом. `.gitignore`
  исключает их из репозитория.
- Используемые модели (WhisperX, GigaAM, pyannote, модели разделения вокала)
  распространяются под своими лицензиями; для `pyannote/segmentation-3.0`
  нужно принять условия на HuggingFace.
